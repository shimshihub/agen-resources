Phase 1 - Deep Dive: Prep and Upload a New List

Step A. Start from a safe copy

  1. Open the list spreadsheet and go to the new list tab The link posted in the Slack channel is the source of truth. Work off it, never in it.
  2. File > Make a copy All the deleting that follows happens in the copy, so the original data is never lost. No special name needed, it's just the working file. Double-check you are on the correct tab before touching anything.

Step B. Rename and clean the columns

The whole point of renaming is that the headers then auto-map in the Salesforce import wizard. Exact spelling matters; capitalization does not.

EmailKeep as is.
Email StatusDelete.
LinkedIn_URLKeep, rename to LinkedIn URL (underscore to space). Spot-check one value to confirm it is the person URL, not the company.
First_Name / Last_NameKeep, fix to First Name / Last Name.
TitleKeep as is.
Simplified title, department, location fields (roughly F through K)Delete. Check each has nothing we need first (highlight the column, look at the count, or Cmd+Down to check for values).
Company NameRename to Account Name.
Company Domain / WebsiteDuplicate the column. Name one Account Website and the other Contact Website.
Company LinkedInSpot-check it is the company URL, then duplicate. Name them Account Company LinkedIn URL and Contact Company LinkedIn URL.

Add a handful of empty columns at the far right before you start the phone work. You will need the space for moving columns around.

Step C. Phone numbers - split, label, consolidate

  1. Check every phone column for data Highlight each column and look at the count. Delete any phone column that is completely empty.
  2. Split the aggregated columns The raw lists pack many numbers into one cell separated by semicolons. For each column like that: move it to the end of the sheet, then Data > Split text to columns > separator: semicolon. Repeat for every column holding multiple numbers, and check the last split column each time to confirm nothing spilled further.
  3. Rename the resulting phone columns In order: Mobile, Contact Phone, Phone 2, Phone 3, Phone 4, Phone 5, then Phone 6, Phone 7... for the overflow. Salesforce only takes the first six (Mobile plus Contact Phone plus Phone 2 to 5).
  4. Add the status columns Insert a status column after each of the first six phone fields, named exactly: Mobile Status, Contact Phone Status, Phone 2 Status, Phone 3 Status, Phone 4 Status, Phone 5 Status. These exist in Salesforce and must map. No status columns for Phone 6 and up - those never go to Salesforce.
  5. Tag international numbers as NA - INTL For each of the six phone columns: sort the column Z to A so the plus-prefixed international numbers group together, and in its status column write NA - INTL for every non-US number (anything not +1).
    • Why not delete them: NA means "needs attention" in the Titan X world - these get skipped in scoring, which saves credits, but the numbers still reach Salesforce in case we ever run an Australia or UK campaign.
  6. Rescue numbers from the overflow columns For Phone 6 and up, sort each column Z to A and move any usable US number into an empty slot among the first six. A US number beats an international one, so you can even overwrite an INTL number with a US one from the overflow (the INTL data can be recovered later from Salesforce report comparisons if a second scoring pass is ever needed). Tip: select a whole run of numbers and cut-paste them together into one target column instead of one by one. Always move numbers as far left as possible.
  7. Final phone sweep, then delete the overflow Check Phone 5 (sort Z to A) for anything that can move left into an empty earlier slot. Then delete all Phone 6+ columns entirely.

Step D. The two mandatory fields at the end

  1. Contact Type Add a column named Contact Type. The value is the persona segment, for example the CIO ITBA value. Do not guess the syntax: open Salesforce, open the CIO ITBA report (bookmarked), copy the exact contact type value from a row, paste it in and fill down. No list number goes here.
  2. Campaign / List Name Add a column named Campaign / List Name. Get the exact current value from the "export for scoring" template report filter in Salesforce, then increment both numbers: the first number is the running total of all lists ever uploaded, the second is the list number within the segment. Example from the sessions: after "24 ... 16" came 25 - CIO ITBA 17. Fill down all rows.

Step E. Import to Salesforce

  1. Download as CSV Name it with "up" in it (for example "List 17 up") so you know it is the Salesforce upload file among all the downloads.
  2. Open the Data Import Wizard Salesforce > gear icon > Setup > type "import" in Quick Find > Data Import Wizard > Launch Wizard.
  3. Wizard settings for a NEW list
    • Object: Accounts and Contacts
    • Action: Add new records
    • Match Contact by: Email
    • Match Account by: Name & Site
    Matching finds duplicates: a matched contact is not created again, but its fields (like a fresh phone number) may update on the existing record. The Campaign / List Name field is configured in the back end not to override on update, which is exactly what lets us isolate the new contacts afterwards.
  4. Upload the CSV and verify the mapping Every header should map automatically with no warning icons. Typical fixes: Company Name must be Account Name, and the phone field must map to the contact phone, not the account phone. Fix stragglers, hit Next, Start Import. It runs in batches, about two minutes.
  5. Check the result Setup > Data Import Wizard area shows records created / updated. For a deeper look: Bulk Data Load Jobs > click the contact job ID > View Result downloads a log file where you can count errors.
    • Created = genuinely new contacts (these are what goes to scoring).
    • Updated / matched = already existed, skipped as new.
    • A small failure count (formatting, missing data) is normal; around 2 percent was typical.
    • If the duplicate share is unusually high (40 percent happened on list 16), flag it in Slack and investigate the source list for overlap with previous lists.

Step F. Export for scoring and hand off to Andrew

  1. Open the "export for scoring" template report Update its campaign list name filter to the new value (for example "25 - CIO ITBA 17") and refresh until the count stabilizes. Because campaign list name does not override on existing contacts, this report returns only the newly created contacts - all with today's created date and a blank bucket status.
  2. Export it Report arrow > Export > Details Only > CSV.
  3. Clean the export
    • Filter each phone status column for NA - INTL and delete those phone numbers (just the numbers in the phone column, per the tag).
    • Then delete all six status columns entirely.
    • Drop any leftover columns that are not in Andrew's headers template.
  4. Send the CSV to Andrew in Slack He uploads it to Titan X under his account. Scoring takes days. Phase 1 done.

The Handoff - What Titan X Sends Back

Andrew messages back with the scored CSV ("list N is final"). What is in it:

  • Every contact with every phone number, each number carrying a score: P1 is a confirmed-good number (the ones that get dialed), down to P3 and bad data.
  • SF flag means the number went through a spam filter or AI screener, but if the person still picked up, it stays a P1.
  • IVR columns capture the phone path (extensions, dial-through directories).

You only ever touch this file after Andrew sends it. There is no Titan X login on our side; Andrew is the Titan X manager and credits are purchased through him.

Phase 2 - Deep Dive: Upload the Scored File

  1. Clean the Titan X file down to the template
    • Delete the leading junk columns (in the session run: everything from A through J, up to and including the best-phone block).
    • Keep the Contact ID column - that is the Salesforce.com ID and it is what the import matches on.
    • Delete every phone-specific IVR column. Keep the one general IVR navigation column - it aggregates the per-phone paths.
    • Delete the remaining columns not in the template (go by the template, not by column letter - it shifts between runs).
    • End state: columns A through M matching the headers template. Copy the template's header row and paste it over your headers so they are exact.
  2. Download as CSV Same habit: short name (Salesforce has a length limit) with "up" in it.
  3. Data Import Wizard - settings for a SCORED file
    • Object: Accounts and Contacts
    • Action: Update existing records (they all exist now)
    • Match by: Salesforce.com ID
    • CRITICAL: check the "trigger workflow rules and processes" checkbox. In Andrew's words: "this is where everybody messes something up." Without it, the downstream automation (bucket status, Frontspin sync) does not fire.
  4. Upload, verify mapping, start import Everything should map cleanly since the headers came from the template.
  5. Verify on the Frontspin P1 report Open the post-scoring report (a different report from the scoring export - this one is connected to Frontspin; filters: contact type CIO ITBA, company over 49 employees, bucket status P1, across all lists ever). Hit refresh and watch the total grow - in the session it went 1849 to 1965, meaning 120 fresh P1s pushed to the dialer. That growth is the confirmation the import worked.
Done. The P1s are now in the Frontspin call list automatically. Nothing else to push.

Quick Checklist (print this part)

Phase 1 - new list in:
  • Make a copy of the list tab (never edit the original)
  • Rename headers to Salesforce names; delete unused columns; duplicate Website, Company LinkedIn, Company Size into their Account/Contact pairs
  • Split semicolon-packed phone columns (Data > Split text to columns)
  • Rename phones: Mobile, Contact Phone, Phone 2-5, then overflow Phone 6+
  • Add the six status columns (Mobile Status ... Phone 5 Status)
  • Sort each phone column Z-A, tag non-US numbers NA - INTL in the status column
  • Move usable US numbers from Phone 6+ into free slots, then delete Phone 6+
  • Add Contact Type (exact value copied from the Salesforce report)
  • Add Campaign / List Name (increment both numbers, e.g. 25 - CIO ITBA 17)
  • Download CSV ("... up"), Data Import Wizard: Add new records, match Email + Name & Site
  • Fix mapping warnings (Account Name, contact-level Phone), import, check created vs duplicates
  • Update the scoring report filter to the new list name, Export > Details Only
  • Delete NA - INTL numbers, delete status columns, send CSV to Andrew
Phase 2 - scored file back:
  • Delete leading columns; keep Contact ID; keep only the general IVR column
  • Paste the template headers (columns A-M)
  • Data Import Wizard: Update existing records, match by Salesforce.com ID
  • CHECK "trigger workflow rules and processes"
  • Import, then refresh the Frontspin P1 report and confirm the count grew

Good to Know

  • Dialing lifecycle: the caller makes 7 attempts over 2 weeks per contact; after that they drop into a no-answer bucket automatically. The FS Total Calls field on the contact shows attempt counts. Reactivate lists are generated off bucket status, not contact type.
  • Feeding the machine: plan a new list every week or two. Andrew can rescore previous lists to buy time between fresh ones.
  • Reference material: Andrew's written headers template (shared in Slack) is the source of truth for the Phase 2 column layout, and his video library covers list ops, Salesforce setup, Frontspin and Titan X in more depth - ask Ori for access.
  • Why duplicates are matched, not rejected: if someone is on a list we sent, the assumption is we want them called (maybe with a better number), so existing records get their data refreshed while only genuinely new contacts are created and scored.
  • Questions: process and Salesforce questions go to Ori; Titan X and scoring questions go to Andrew.
